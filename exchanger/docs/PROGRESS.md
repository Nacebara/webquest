### Мульти-чеки — решение владельца (11 октября 2026, DESIGN-v0.2 Р8)

- Мульти-чеки xRocket (`mci_…`, `mc_…`) активируются только в приложении xRocket: парсер отдаёт `LinkError::MultiCheck` в любой форме ссылки и голым кодом, движок дополнительно не пускает их в `submit_check`. Клиенту — экран E08 «деньги остались в чеке».
- Мульти-чеки CryptoBot (`CQ…`) — как обычные чеки, зачисляется наша доля.
- Чек, который мы уже открывали (вторая доля того же мульти-чека из канала, повтор старого чека, прошлый чек живого счёта), — отказ `check_used` без второго `/start`. Раньше в этом случае падал уникальный индекс `operations_check_once` с внутренней ошибкой. Тот же отказ — если чек сейчас в живой заявке другого клиента (чужой номер заявки не показываем).
- Ревью (4 проверяющих, по 2 скептика на находку): 7 подтверждённых и 3 спорных находки исправлены — ранжирование ошибок ссылок, повтор отклонённого чека в свой счёт, тексты `check_used`/E08/условий, SPEC.

Тесты: 460.

### Третья запись: активация своих чеков (6 ноября 2026)

- Третья запись (408 сообщений после очистки) — в живых фикстурах: 153 случая из трёх записей. Все 75 текстов с «получ» / «оплатил» во всех записях разобраны верно: выигрыш — `Received` с точной суммой, уведомления (и «… оплатил(а) ваш счёт. Вы получили …») — `ClaimNotice`, «… от X» — входящий перевод, чужая монета — `ReceivedOther`.
- Точные ответы при активации: CryptoBot «📥 Вы получили 🪙 0.021025 USDT ($0.02).» (правка «🕘 Получение…»), xRocket «💰 Вы успешно получили 3 XROCK (0.09$).» (правка «⏱ Получение…»).
- Свой чек: CryptoBot присылает уведомление «… активировал(а) ваш чек и получил(а) …» между «Получение…» и правкой, xRocket — после правки. Симулятор повторяет оба порядка; тесты: уведомление никогда не ответ, позднее уведомление не достаётся следующей операции.
- Сообщения между операциями сейчас попадают в журнал, только если их увидит следующая операция. Фоновая запись всех сообщений ботов — вместе со сверкой балансов.

### Пульт, ступени, встречный поток, личные условия (6–7 ноября 2026)

- Комиссия (DESIGN-v0.2 Р15): у направления режим «фикс» или «ступени»; встречный поток — выгодный курс только на объём, который выравнивает резервы, режимы выкл / подсказывать / авто с порогами; единый расчёт `domain::fees` для движка, клиентского бота и пульта. Клиент видит «от …», «Комиссия по сумме» и «🔥 Сейчас выгодно … до N USDT».
- Личные условия клиента и лимит новичка (Р16): своя комиссия, минимальная комиссия, лимиты, снятие лимита новичка, свой суточный лимит; лимит новичка выключается и для всех.
- Ручные решения по заявке (`engine::operator`): повторить выплату или оплату, вернуть, закрыть «выплачено» (с доказательством), закрыть без выплаты (владелец), «деньги пришли» — только при проведённом приходе, без живых операций, неясная прежняя попытка — только с явным подтверждением, потолки по ролям, журнал в той же транзакции.
- Пульт (`crates/ops`): сводка, направления (комиссия, ступени ⇄ фикс, рычаг, лимиты, лимит новичка, запас курса, пауза, снятие автопаузы), встречный поток (режим, курс, пороги, цели резерва, включение по направлению), разбор (карточка заявки, решения), клиенты (личные условия, суточный лимит, бан, заметка), настройки (лимит новичка, обслуживание, стоп-кран, премиум-эмодзи: вариация и свой эмодзи на роль), юзерботы (пауза аккаунта — исполнитель её соблюдает), персонал, журнал; события в личку персоналу с «Открыть» / «Включить» / «Принял». Любое изменение — предпросмотр «было → станет» и одноразовое подтверждение; изменение комиссии больше 1 п.п. — только владелец. Тексты — `crates/ops/ru.toml`. 8 сквозных тестов на поддельном Bot API + движок на симуляторе + PostgreSQL.
- Клиентский бот подхватывает смену эмодзи из пульта без перезапуска (раз в минуту сверяет настройки).
- Новые значки семьи exch: «Выгодно» (🔥), «Встречный поток», «Ступени»; причины разбора и автопаузы — по-русски.

### Сверка балансов, самопроверка, деплой (7 ноября 2026)

- Сверка (SPEC П14): раз в 10 минут баланс USDT каждого кошелька через юзербота против леджера; при операциях в полёте и во время самопроверки замер откладывается. Не хватает денег сверх допуска — выплаты с кошелька на паузу и CRITICAL; денег больше (владелец пополнил) — событие с кнопкой «Это мой взнос: провести» (`capital_in`), меньше — «Это мой вывод» (`capital_out`), только владелец. Кнопка «Сверить балансы» в сводке.
- Самопроверка: на каждом кошельке чек через меню на 1 USDT и его же активация, баланс тот же, леджер не меняется — кнопкой в пульте или `exch selftest`.
- Деплой: `Dockerfile` (многоэтапный, distroless), `deploy/docker-compose.yml`, бэкап `pg_dump → age → rclone` по таймеру systemd, `docs/DEPLOY.md` — от пустого сервера до первого живого прогона по 1 USDT. Релизная сборка без базы (`SQLX_OFFLINE`, `--locked`) проверена; образ здесь не собран — демона Docker в среде нет.

## Известные проблемы и решения по ходу

- Многоразовый счёт CryptoBot по записи — всегда без суммы («Пришлите сумму…»): не оплачиваем. Многоразовый счёт xRocket в записях не попадался; признак — слово «многоразовый» / «мульти-счёт» на экране, если бот его пишет. Повторно «Оплатить» бот не нажимает никогда.

- `schema.sql` больше не оборачивает себя в `BEGIN/COMMIT`: sqlx сам выполняет миграцию в транзакции. Вручную — `psql -1 -f schema.sql`. Пока проект не развёрнут, `schema.sql` = `migrations/0001_init.sql`. После первого деплоя `0001` замораживается: изменения идут новыми миграциями, а `schema.sql` превращается в снимок схемы (`pg_dump --schema-only`). Тест на равенство тогда заменим на сравнение снимка.
- В схему добавлены виды проводок `excess_kept`, `manual_close` (нужны шаблонам леджера; `app_topup` удалён в v0.2). Ничего не задеплоено, поэтому это правка `0001`, а не новая миграция.
- Интеграционные тесты `storage` требуют `DATABASE_URL` к PostgreSQL с правом создавать базы: `sqlx::test` создаёт отдельную базу на каждый тест.
- Макросы `sqlx::query!` при сборке без БД берут данные из `.sqlx/` (`SQLX_OFFLINE=true`). После изменения SQL — `cargo sqlx prepare --workspace -- --all-targets` и коммит `.sqlx/`.
- `exch run` запускает движок, только если есть `TG_API_ID`, `TG_API_HASH`, `SESSION_KEY` и хотя бы один кошелёк после `exch login`; клиентский бот — если ещё есть `CLIENT_BOT_TOKEN`. Живьём не проверено: сеть к Telegram в среде разработки закрыта.
- `SPEC.md` и диаграммы переписаны под v0.2 (10 октября); вопросы к владельцу — HANDOVER §8.1.
- CI собирает и тестирует с `--all-features`, иначе тесты симулятора (feature `sim`) не запускаются.
- CI на GitHub Actions зелёный с первого прогона ([run 37548527139](https://github.com/Nacebara/webquest/actions/runs/37548527139), ≈ 3,5 мин).
