## 2. Главное из аудита (проверено мной по коду)

Это не полировка, а **ошибки**: клиент видит неправду или упирается в тупик.

1. Суточный лимит и остановка выплат приходят клиенту как «Что-то пошло не так у меня»
   (`tgbot/src/orders.rs`, `reject_error` знает 4 кода из 6).
2. «Нажмите кнопку — напишу, когда заработает» — кнопки нет (`ui/ru.toml`, `[errors] paused`).
3. «Создайте чек в любом чате» — чек на предъявителя, в группе его заберёт посторонний
   (`invest.deposit`, виджеты `calc_a`, `calc_b`: «вставьте в любой чат»).
4. Поддержка: нельзя отменить вопрос и нельзя ответить оператору (Д7/С3 приняты, в коде нет).
5. Чек не в USDT: «Кошелёк не ответил вовремя» — неправда, деньги уже у сервиса (К-3).
6. «Закрыта оператором» — ни слова, где деньги (Д9 принята, в коде нет).
7. Сообщение с чеком выплаты можно переслать — чек заберёт получатель (`protect_content` не ставим).
8. Зелёная «Забрать» навсегда, даже когда чек давно забран — «украли?».

Пульт (П-1…П-4):

9. Неясная выплата: красная «Проверил — подтверждаю» без суммы, а «Повторить выплату» стоит
   первой, даже когда сверка видела, что выплата прошла, — прямой путь к двойной выплате.
10. «Взять» ничего не закрепляет: двое сотрудников могут принять противоречивые денежные решения.
11. «Принял» оператора гасит тревогу у всех, а решить он не может (нужен админ) — заявка висит
    до утра. Нужна кнопка «Позвать админа».
12. Ссылку на чек, вставленную сотрудником в пульт, бот открывает как клиентскую.

Бэкенд: бот не был подписан на правки сообщений — самый быстрый способ поймать ссылку на чек из
инлайн-режима кошелька не работал с первого коммита. **Исправлено 16.11** (А-1, тест на подписку).

Виджеты (код готов, Telegram их пока выключил — чиним сейчас, чтобы к включению были безупречны):
ползунок меняет сумму при прокрутке чата; кнопка «нажмите ещё раз» остаётся выключенной; список
очереди пересобирается каждую секунду и теряет нажатия; вывод шлёт номер позиции, а не сумму;
отсчёты верят часам телефона; строки из профилей через `innerHTML` (фишинговая кнопка в пульте);
контраст янтарного текста 2,9 : 1 при норме 4,5; зоны нажатия меньше 44 px.

## 3. Bot API: что используем и что — нет

Используем: rich-сообщения (таблицы, раскрывашки, подвал, время в поясе читателя, графики
картинкой), премиум-эмодзи в тексте и на кнопках, цвет кнопок, кнопки «скопировать», 19
виджетов с запросами к боту.

Не используем, а стоит (точный список с первоисточниками — отчёт аудитора платформы):

| Возможность | Что даст exch |
|---|---|
| Общее состояние виджета (`public_data`) | «Курс» и «Выгодно» обновляются у всех клиентов одной правкой; «Выгодно» гаснет само |
| Фоновый запрос виджета при открытии | Свежие цифры и верное время в отсчётах, без опоры на часы телефона |
| Реакция бота на сообщение | 👀 на присланную ссылку за долю секунды — «увидел», ✅ на итог |
| Эффект сообщения (конфетти) | Первый обмен клиента — праздник без лишнего текста |
| Запрет пересылки (`protect_content`) | Чек выплаты не уйдёт в чужой чат |
| Неактивная кнопка (`disabled`) | «Отправляю…» в пульте — нет двойных нажатий |
| Кнопки внутри текста (`tg-button`) | Действие прямо в раскрывашке «Помощи» и в строке «Очереди» |
| Inline-режим нашего бота | `@бот 100` в любом чате → карточка курса другу с кнопкой «Обменять» — рост |
| Ссылки `?start=` | Реферальная программа; «оплатить этот счёт» одной ссылкой из магазина |
| Описание бота с картинкой или анимацией | Первый экран до /start — с нашим логотипом и тремя шагами |
| Общие виджеты (`sendSharedWidget`, `editSharedWidgetData`, `public_data`) | «Выгодно» и «Курс» — одна правка на всех получателей, без лимита рассылки |
| Тихая правка виджета (`editMessageWidgetData`) | Живая заявка обновляется без пометки «изменено» |
| Размеры виджета (`width`/`height`) | Виджет не прыгает по высоте при загрузке |
| Эффект в `sendWidget` | Конфетти прямо на живой заявке в момент «Готово» |
| `openTelegramLink` в виджете | «Обменять» из «Выгодно» и карточка заявки из «Очереди» — без запроса к боту |
| Анимированная аватарка (`setMyProfilePhoto` + `InputProfilePhotoAnimated`, Bot API 9.4) | Живой логотип в списке чатов: MP4 до 1080×1080, советуют 800×800; неподвижный кадр задаётся |

## 4. Свежие решения (что сделает бот лучшим на рынке)

1. **Мгновенный отклик**: реакция за 100 мс + живая заявка — ни секунды тишины.
2. **Чек под защитой**: запрет пересылки + бот видит, что чек забран («забрали в 14:05», кнопка
   гаснет); чек не забран сутки — напоминание (наш «Чек не забран», вариант А).
3. **Честный лимит заранее**: в «Курсе» — сколько можно обменять в каждую сторону прямо сейчас;
   клиент не упирается в «нет резерва».
4. **Подписка на возобновление**: пауза → «Сообщить, когда заработает» — и бот правда пишет
   одному этому клиенту.
5. **«Выгодно» без спама**: срок в тексте, «Не присылать» одной кнопкой, погасшие предложения
   правятся сами.
6. **Английский язык** с первого дня: Telegram международный, тексты уже в `ru.toml` — нужен
   `en.toml` и выбор по языку клиента.
7. **Друг приводит друга**: ссылка `?start=` — обоим скидка на комиссию (личная комиссия в
   пульте уже есть).
8. **Сумма числом**: клиент пишет «150» — получает готовую квитанцию и команду кошелька.
9. **«Как в прошлый раз»**: повтор обмена одним касанием.
10. **Пульт — конвейер «Следующее дело»**, смена и дежурный (звук только ему), второе
    подтверждение другим сотрудником на крупные суммы, клиенту сразу «Оператор Анна занялась
    заявкой».
11. **Словарь**: одни деньги — одно слово везде («Вы прислали», «Вы получите», «у меня / в вашем
   чеке / у вас»), держится тестом.

## 5. Что дальше — мой совет

Интерфейс **не закончен**: восемь пунктов раздела 2 — это ошибки, а не вкус. Предлагаю
**спринт укрепления интерфейса**, без новых экранов:

1. Ошибки раздела 2 + принятые тексты и концепция Б в коде.
2. Код виджетов: все находки аудитора — пока Telegram их выключил, это бесплатно.
3. Пульт: находки аудитора, 74 обычных эмодзи → наши значки.
4. Новые возможности API из раздела 3: реакции, запрет пересылки, эффект, общее состояние
   виджета, неактивные кнопки.

Потом **заморозка интерфейса** и бэкенд — вехи 3–5 плана: деньги и сверка, развёртывание,
мониторинг, резервные копии. Затем **пилот на 5–10 своих людях** с настоящими деньгами
небольшими суммами — и только потом запуск.

Спорю в одном: «идеал» нельзя нарисовать в макетах. Ни один аудит не заменит десять живых
людей, которые первый раз меняют свои деньги. Пилот покажет то, чего не видим мы с вами.

## 6. Решения, которые нужны от владельца

1. **Квитанции денежного потока** («Пришлите чек», «К оплате», «Жду чек», «Не хватает»):
   А — обычный HTML, как весь денежный поток (советую: в Telegram Web и старых приложениях
   rich-сообщение бывает заглушкой «не поддерживается», а «Простого вида» больше нет);
   Б — оставить rich.
2. **Моно**: А — только то, что копируют: номер заявки, команда, сумма к оплате (советую:
   в Telegram моно окрашен, и красная сумма в «Готово» выглядит как ошибка); Б — все суммы.
3. **Запрет пересылки сообщения с чеком**: А — да (советую); Б — нет, только строка «не
   пересылайте».
4. **Логотип** — номер концепции (советую 3 — «e → стрелка»: свой знак, читается в 28 px).
5. **Порядок**: спринт укрепления → бэкенд → пилот → запуск (советую).
6. **Анимированная аватарка**: А — да, живой вариант выбранной концепции (советую); Б — статичная.
