# PLAN-v1 — exch по утверждённым макетам

Составлен 8 ноября 2026 после независимого аудита. **Цель — утверждённый макет**
(`docs/mockups/template.html`): путь клиента в варианте B1, главный экран пульта «вариант А» в трёх
состояниях, «Карта пульта» из 50 экранов, «Что под контролем», «Эмодзи v2», правила интерфейса.
Гарант «Оплот» (`oplot-bot`) — источник **техники**, на которой макет удобно построить
(карточки rich + запасной HTML, «одно окно», настройки «поле → значение → было/стало»), а не образец
внешнего вида.

Статусы: ✅ сделано и принято владельцем · 🛠 логика есть, экран переделать по макету · ⬜ нет, сделать ·
➕ моё предложение сверх макета (делаю только после «да» владельца).

## 0. Правила работы

1. **Источник правды по виду — макет.** Каждый экран сверяется с макетом построчно: текст, порядок
   строк, эмодзи, цвет и подписи кнопок. Расхождение — только по согласованию.
2. **«Готово» говорит владелец**, а не тесты: каждый экран он видит у себя в Telegram через
   «Предпросмотр экранов» и ставит «принято» или пишет замечание. Таблица приёмки — в конце файла.
3. **Работаю по порядку фаз.** Вопрос посреди работы — ответ, пункт в нужную фазу, продолжаю с того же
   места.
4. **Деньги не ломаем:** ядро не переписываем; новые денежные функции — только после живого прогона.
   Схема базы — **только новыми миграциями** (0001 заморожена с 8 ноября: у владельца база уже есть).
5. **Каждая фаза закрывается** ревью кода (`/engineering:code-review`), проверкой перед выпуском
   (`/engineering:deploy-checklist`) и отчётом независимого аудитора: что из макета сделано, что нет.
6. **Запуск — как гарант у владельца:** папка проекта, `cargo build --release`, программа в
   `target/release`, PostgreSQL владельца, `.env` (секреты) + `config.toml` (остальное). Без Docker,
   exe-рассылок и батников.

## 2. Фаза 1 — основа интерфейса (на ней строится всё остальное)

**Сверено со спецификацией Bot API 10.3** (`docs/BOTAPI-RICH.md`, 8 ноября):
- rich-сообщение принимает `html`, `markdown` или `blocks` — формат exch (`html`) официальный, переписывать на блоки не нужно;
- **графики — прямо внутри карточки статистики**: PNG передаётся в `media`, в тексте — `<img src="tg://photo?id=…">` (лучше, чем отдельное фото под карточкой);
- время — `<tg-time>`: каждый видит в своём часовом поясе;
- премиум-эмодзи в тексте и на кнопках (`icon_custom_emoji_id`) работают, только если у владельца бота Telegram Premium — иначе автопереход на обычные (1.2);
- неактивная кнопка `disabled` — для состояний «Отправляю…»; кнопки внутри текста `<tg-button>` — где макет ставит действие в строку.

| # | Что | Почему |
|---|---|---|
| 1.1 | **Карточки**: одна модель экрана (заголовок со значком, крупная сумма, строки «ключ — значение», таблица, чек-лист шагов, раскрывашка, заметка, подвал) → rich-сообщение блоками + запасной HTML. Перенос из `oplot-bot/src/ui/card.rs`, `telegram/rich.rs` | Сейчас пульт — склейка строк, клиент — rich HTML-строкой. У гаранта формат блоков проверен вживую |
| 1.2 | **Отправка карточек** с запасными путями: rich не принят → HTML; кастомные эмодзи не приняты → обычные; запоминать отказ | `oplot-bot/src/service/messaging.rs` |
| 1.3 | **Эмодзи везде**: роли по макету «Эмодзи v2» — цветные статусы (`dot_ok/dot_wait/dot_act`), шаги (`step_done/step_now/step_todo`), кольца прогресса (`prog_25/50/75`), `process` (точки «в работе» — выбор владельца), `sending`, `alarm`, `live`; линейные — на кнопках | Сейчас используется 21 роль из 116 значков, в пульте — ни одной |
| 1.4 | **Кнопки по смыслу**: зелёная — забрать деньги, синяя — главное действие, красная — необратимое; иконка — из эмодзи роли | Правило макета «Цвет кнопки = смысл» |
| 1.5 | **Одно окно** для навигации (пульт и справка клиента): правка того же сообщения, ввод пользователя удаляется, вопросы — с полем ответа сразу | Сейчас каждый экран пульта — новое сообщение |
| 1.6 | **Состояние диалогов, подтверждений и алертов — в базе** (сейчас в памяти, теряется при перезапуске) | Правило «Алерт правится, а не множится» не выполняется после перезапуска |
| 1.7 | **Картинки для графиков и плиток**: SVG по стилю макета → PNG на сервере; светлая и тёмная тема | Telegram не рисует графики внутри rich-сообщения — только картинкой |
| 1.8 | **«Предпросмотр экранов»** в пульте: бот присылает владельцу каждый экран клиента и пульта настоящим сообщением с отметкой «принято / замечание» | **Клиент — сделано** (демо: `/preview`, `exch demo --preview`; порядок и данные макета). Пульт — по мере переноса |
| 1.9 | Снимки-тесты для **каждого** экрана пульта (rich + HTML) | У пульта сейчас ни одного снимка |

## 7. Порядок и сроки (честно)

| Фаза | Срок | Владелец проверяет |
|---|---|---|
| 0. Живой прогон | 1–2 дня | обмены по 1 USDT, чек через `@send`, лимиты, эмодзи |
| 1. Основа интерфейса + Предпросмотр | 2–3 дня | Предпросмотр приходит в Telegram |
| 2. Пульт по макету | 5–7 дней, частями: сводка → меню и настройки → деньги и направления → статистика → аккаунты → тревоги → рассылка → система | каждый экран в Предпросмотре |
| 3. Клиент B1 | 2–3 дня | Предпросмотр + живой обмен |
| Надёжность | параллельно | Система, бэкап |

Итого до «как в макете» — около 2–3 недель работы, с приёмкой по частям каждые 1–2 дня.

## 8. Нужно от владельца

1. Ошибка установки эмодзи (текст).
2. Строка «баланс не читается» из «Сверить балансы» (после замены `exch.exe`).
3. Токен: у exch свой бот или общий с гарантом? Если общий и гарант работает — нужен свой.
4. «Да» на правила проекта в `CLAUDE.md`: интерфейс — только по макету, на карточках, с эмодзи; «готово» — после проверки владельцем; миграции — только новые.
5. Предложения П1–П6: какие делать.
