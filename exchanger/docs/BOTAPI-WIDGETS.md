# Виджеты Bot API 10.4 — выжимка для exch

Источник: core.telegram.org/bots/widgets и core.telegram.org/bots/api (Bot API 10.4, 9 ноября 2026),
прочитано 13 ноября 2026. Здесь — только то, на чём строятся предложения
`docs/mockups/widgets/` (страница предпросмотра — `build.py` в той же папке). Статус: **предложение,
владелец не утверждал**; в коде exch виджетов пока нет.

## Что это

- Виджет — один HTML-документ (встроенные `<style>` и `<script>`), который Telegram рисует **внутри
  пузыря сообщения** и выполняет на устройстве: JavaScript в QuickJS, не в WebView. Сети нет совсем
  (`fetch`, `XMLHttpRequest`, `WebSocket` бросают ошибку), внешние скрипты, шрифты и картинки не
  грузятся. Картинки — только `data:` PNG/JPEG/GIF/WebP и встроенный SVG.
- **Код задаётся при отправке и больше не меняется.** Меняется только состояние, и пишет его только
  бот: `chat_data` (к одному сообщению) и `public_data` (общее), каждое до **1024 байт UTF-8**.
  Виджет узнаёт о смене событием `chatDataChanged` / `publicDataChanged` и перерисовывается.
- Виджет может спросить бота: `TelegramWidget.request(data)` (1–64 байта) → обновление
  `widget_query` → бот отвечает `answerWidgetQuery` (до 1024 байт) **в течение 15 секунд**. Ответ
  получает только спросивший виджет; состояние ответ не меняет.
- Подпись (`caption`, до 1024 символов, с сущностями — значит, и с премиум-эмодзи; проверить вживую)
  и инлайн-клавиатура под виджетом работают как у фото. Подпись правится `editMessageCaption`.

## Где работает (важно для exch)

| | Бой (production) | Тестовый сервер |
|---|---|---|
| Личный чат с ботом | да | да |
| Группы, инлайн-режим | **нет** | да |
| Пересылка | **нет**: виджет всегда «защищённое содержимое» | да |
| Каналы | нет | нет |

Клиент exch и пульт (отдельный служебный бот) — личные чаты: подходят. Приложение без поддержки
виджетов показывает «неподдерживаемое сообщение» **и подпись** — поэтому главное всегда дублируется в
подписи и на кнопках. `copyMessage` виджеты не копирует.

## Методы и поля (сверено по странице Bot API)

- `sendWidget(chat_id, html, width?, height?, public_data?, chat_data?, caption?, parse_mode?,
  caption_entities?, show_caption_above_media?, allow_queries?, is_shared?, protect_content?,
  reply_markup?, …)` → `Message` с полем `widget`. `html` — 1–32768 байт и **не больше 4096 байт
  после zlib уровня 9**; иначе `INPUT_MEDIA_WIDGET_TOO_LARGE`.
- `editMessageWidgetData(chat_id, message_id, public_data?, chat_data?)` — пустая строка стирает,
  пропуск оставляет как было. Считается как одно отправленное сообщение в лимитах бота.
- `answerWidgetQuery(widget_query_id, data?)`. Ответить надо на **каждый** запрос, иначе у виджета
  `TIMEOUT`.
- `WidgetQuery`: `id`, `from` (подделать нельзя), `chat`, `message_id`, `chat_instance`, `type`,
  `data` (1–64 байта, **недоверенный ввод** — сверять с тем, что хранит бот), `widget_id`.
  Не больше **5 запросов за 5 секунд** от одного пользователя ко всем виджетам бота.
- В `allowed_updates` нужны `widget_query` и `shared_widget_query`.
- Ещё: `sendSharedWidget`, `editSharedWidgetData`, общие виджеты (`is_shared`), оплата и подпись через
  кошелёк TON — exch это не нужно.

## Запросы без нажатия

Только в личном чате с ботом и только пока виджет на экране: один запрос при появлении, потом не чаще
раза в 5 секунд. На этом построен «Живой пульт»: открыт — сам спрашивает свежие цифры; бот не ответил
дважды — показывает «Бот не отвечает». Остальные запросы — только в обработчике нажатия, по одному.

## Что внутри можно и нельзя (профиль 1, кратко)

- Можно: flex/grid, `position`, градиенты, тени, `transition`/`@keyframes`, `light-dark()`,
  `color-scheme`, `@media (prefers-color-scheme / prefers-reduced-motion / min-width)`, SVG-фигуры,
  canvas 2D, указательные события, `copyText` (на нажатие), `openTelegramLink`, вибрация.
- Нельзя: поля ввода (`input`, `select`, `textarea` — вырезаются, **ввести сумму с клавиатуры нельзя**),
  прокрутка внутри (`overflow: auto` → `hidden`), `vh`, `@font-face`, `clip-path`, маски, `oklch()`,
  `color-mix()`, `:has()`, `alert/confirm`. Вертикальные жесты всегда у чата.
- Размер: ширина пузыря 200–600 px (на телефоне 320–430), высота 50–600 px, лишнее обрезается.
- Цвета — переменные темы `--tg-theme-*`; тёмная тема чата включает `prefers-color-scheme: dark` и
  `light-dark()` внутри виджета (не системная тема).
- Прозрачность ниже 1, фильтры и размытые тени — не больше 16 элементов одновременно; приглушать
  цветом. 400 правил CSS, 2000 узлов, 8 МБ памяти, 64 таймера; превышение — виджет «остановлен».
- Время сообщения рисуется поверх правого нижнего угла виджета, если подписи под ним нет:
  отступ `env(safe-area-inset-bottom)` / `--tg-content-safe-area-inset-bottom`.

## Правила exch для виджетов (из предложения; станут правилами, если владелец утвердит)

1. Деньги считает бот (`domain::pricing`, движок); виджет только показывает готовые строки. Никакой
   денежной арифметики в JavaScript.
2. Всё, что нужно клиенту для денег (сумма, «Забрать», где деньги), — в подписи и на кнопках. Виджет
   добавляет вид, а не смысл.
3. Ошибки, тревоги персоналу, подтверждения необратимого и квитанция — не виджеты.
4. Состояние — без секретов и ссылок на чеки; в запросе виджета — только короткая команда (`dash`).
5. Каждый виджет проверяется сборщиком на лимиты (32 КБ / 4 КБ сжатыми / 1 КБ состояния) и вживую на
   тестовом боте: светлая и тёмная тема, телефон и компьютер.
