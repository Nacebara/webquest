# Запись настоящих ответов кошельков

Бот не угадывает, куда нажимать. Каждый экран, кнопку и ответ CryptoBot и xRocket он должен
узнавать по настоящему образцу. Образцы снимаются один раз. Владелец проходит сценарии руками на
тестовом аккаунте, а `exch record` в это время только слушает и пишет всё в файл. Сам он ничего
не отправляет и ничего не нажимает. Из файла получаются фикстуры для парсеров и сценарии для
симулятора. Тесты прогоняют их при каждом изменении кода.

## Что уже проверено, а что нет

| Что | Откуда сейчас | Статус |
|---|---|---|
| Ссылки и коды чеков (`CQ…`, `t_…`, `mci_…`, `mc_…`), закреплённые id ботов | ловец lovec, боевые логи | **проверено** |
| Открытие чека: `/start <код>`, порядок разбора ответов, ловушки (повтор, «не найден» у свежего чека xRocket, FLOOD_WAIT) | ловец lovec; **запись владельца 6 ноября 2026** | **проверено**: живые тексты обоих ботов — фикстуры `live_wallet_replies.json` |
| Создание чека через меню (DESIGN-v0.2 Р5; инлайн не нужен) | запись 6 ноября | **экраны проверены**: CryptoBot — мультичек и «Пропустить ›», xRocket — подтверждение правкой меню, удаление |
| Оплата счёта кнопками в чате, без код-пароля (Р4, Р12) | запись 6 ноября | **экраны проверены** у обоих: выбор монеты, способ оплаты, подтверждение, «Выберите сеть…», доверие получателю, квитанция |
| Экран «Кошелёк» (с удержанием), «… активировал(а) ваш чек…», входящий перевод | запись 6 ноября | **проверено** |
| Многоразовый счёт CryptoBot | запись 6 ноября, второй проход | **проверено**: сумму выбирает плательщик («Пришлите сумму USDT…») — такой счёт не оплачиваем; уведомление создателю «… оплатил(а) ваш счёт. Вы получили …» — не выигрыш чека |
| Многоразовый счёт xRocket, счёт CryptoBot в USDT (не в долларах), всплывающие окна на нажатиях | — | **не записано** — см. «Что ещё записать» |

Пока строка «не проверено» не закрыта записью, этот сценарий на живых деньгах не включается.

Без записи сценарии тоже не поломают деньги. Любой незнакомый ответ кошелька даёт `Unknown`:
- направление встаёт на паузу;
- приходит алерт;
- заявка уходит человеку.

Вывести деньги можно только одной попыткой. Повторно нажимать «Оплатить» или создавать чек
вслепую бот не будет никогда (CLAUDE.md, правила 4–6 и 13).

## Подготовка

1. **Тестовый аккаунт Telegram.** Не основной и не будущий рабочий. Включите облачный пароль.
   Язык Telegram — русский: так боты ответят по-русски, как будут отвечать в работе.
2. **Деньги:** 5–10 USDT в CryptoBot и 5–10 USDT в xRocket на этом аккаунте.
3. **Второй аккаунт** — ваш основной или знакомого. С него создаются чеки и счета для тестового.
4. **CryptoBot → «Безопасность» → «Лимит без код-пароля».** Запишите, сколько стоит. Для теста
   хватит $500 по умолчанию.
5. **Где запускать** — на ноутбуке (проще) или на сервере.

## Запуск на ноутбуке: `exch listen`

Без базы данных и без сервера. Вход — прямо в терминале. Сессия живёт только в памяти под
случайным ключом этого запуска. На выходе слушатель сам выходит из аккаунта (`auth.logOut`),
и в «Устройствах» сессии не остаётся.

```powershell
.\exch.exe listen                     # спросит api_id, api_hash, телефон, код, облачный пароль
.\exch.exe listen --out rec.jsonl --history 300
```

`api_id` и `api_hash` берутся из `TG_API_ID` и `TG_API_HASH`: из окружения или из файла `.env`
рядом. Если их нет, слушатель спросит, а `api_hash` вводится без эха. Сборка под Windows —
`cargo build --release --target x86_64-pc-windows-gnu --bin exch` (MinGW, `SQLX_OFFLINE=true`).
Нужны только системные библиотеки Windows. Готовый архив с `README.txt` для владельца
собирается из `target/x86_64-pc-windows-gnu/release/exch.exe`.

## Запуск на сервере: `exch record`

`.env` с `DATABASE_URL`, `TG_API_ID`, `TG_API_HASH`, `SESSION_KEY`, затем:

```bash
exch migrate
exch login --label test-1 --platform cryptobot   # номер, код из Telegram, облачный пароль — в терминале
exch login --label test-1 --platform xrocket     # та же сессия, без кода
```

## Запись

На сервере (на ноутбуке запись начинается сама после входа в `exch listen`):

```bash
exch record --label test-1 --out ~/rec-test-1.jsonl --history 300
```

`--history 300` сразу сохранит последние 300 сообщений каждого чата: с @send, с @xrocket и
«Избранное». Если тестовым аккаунтом уже пользовались ботами, это готовые образцы. Дальше запись
идёт, пока не нажмёте Ctrl-C.

Пока запись идёт, сделайте руками в Telegram на тестовом аккаунте шаги ниже. Делайте по порядку,
с паузой 5–10 секунд между шагами, чтобы бот успел ответить. Номер шага записывайте на бумажке
или в заметках: так я сопоставлю шаг с ответом.

### А. Кошелёк

1. @send → «Кошелёк».
2. @xrocket → «Кошелёк».

### Б. Создание чека (главное для выплат)

Только через меню (DESIGN-v0.2 Р5): чеки бот делает так же, как человек, и отдаёт клиенту ссылку.

3. @send: `/checks` → «Создать чек» → USDT → `1`. Если бот спросит количество активаций —
   «Пропустить ›». Пройдите до конца и запомните все экраны.
4. @xrocket: `/cheques` → «Персональный» → «Создать чек» → USDT → `1` → «✅ Подтверждаю».
5. @send: откройте список своих чеков, удалите один неактивированный.
6. @xrocket: то же («Удалить» — без сообщения, чек просто пропадает).
7. Сумма больше баланса в обоих ботах — посмотреть отказ.

### В. Открытие чеков (приём денег)

Создайте чеки на втором аккаунте и откройте ссылки тестовым:

8. обычный чек CryptoBot на 1 USDT;
9. тот же чек ещё раз — «уже активирован»;
10. обычный чек xRocket на 1 USDT;
11. мульти-чек CryptoBot на 2 активации по 0.5 USDT;
12. мульти-чек xRocket — бот должен отказать, нужен его ответ;
13. чек CryptoBot, созданный для другого пользователя, если бот это умеет, — «не для вас»;
14. ссылку на несуществующий чек (испортите в ней последнюю букву) — «не найден».

### Г. Оплата счетов

15. Второй аккаунт: @send → «Счета» → создать одноразовый счёт на 1 USDT. Тестовый: открыть
    ссылку → «Оплатить». Запишите, спросил ли бот код-пароль.
16. Открыть ту же ссылку ещё раз — «уже оплачен».
17. Второй аккаунт: счёт на сумму больше баланса тестового. Тестовый: открыть → «Оплатить» —
    «Выберите сеть для оплаты счёта…».
18. То же для xRocket: счёт на 1 USDT → тестовый открыть → «xRocket» → «Оплатить».

### Д. Уведомления

19. Второй аккаунт открывает чек, который тестовый создал в шагах 3–4. Тестовому придёт
    «… активировал(а) ваш чек…».
20. Второй аккаунт переводит тестовому 0.1 USDT напрямую, если бот это умеет. Тестовому
    придёт «Вы получили… от …».

### Е. Что ещё записать (второй проход, 6 ноября 2026)

Первая запись закрыла почти всё. Не хватает трёх экранов:

21. **Многоразовый счёт.** Второй аккаунт: @xrocket → `/invoices` → «Мульти-счёт» на 0.1 USDT;
    @send → «Счета» → многоразовый, если есть. Тестовый: только открыть ссылку, НЕ платить.
    Такие счета бот не оплачивает (при неясном исходе повтор — двойная оплата), и ему нужно их
    узнавать. Сейчас признак — слово «многоразовый» / «мульти-счёт» на экране; если бот его не
    пишет, многоразовый счёт неотличим от обычного.
22. **Счёт CryptoBot в USDT** (не в долларах): второй аккаунт создаёт счёт в монете USDT.
    Тестовый открывает — запишите первый экран: сразу «Подтвердите оплату» или выбор монеты.
23. Ничего не нажимайте на экранах «Выберите сеть…» — эти кнопки ведут к пополнению из сети.

Остановите запись Ctrl-C.

## Передача файла

- **Ссылки:** в файле живые ссылки на чеки. К моменту передачи все тестовые чеки должны быть
  открыты или удалены (шаги 19, 5–6). Тогда ссылки ничего не стоят.
- **Чего в файле нет:** сессии, ключей и номера телефона в нём нет: `exch record` пишет только
  сообщения чатов с ботами и «Избранного».
- **Как передать:** пришлите файл сюда, в чат, вместе со списком «номер шага → что получилось».
  В репозиторий файл не попадает. Коды я замаскирую и сделаю фикстуры.
