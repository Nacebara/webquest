# Запись настоящих ответов кошельков

Бот не угадывает, куда нажимать. Каждый экран, кнопку и ответ CryptoBot и xRocket он должен
узнавать по настоящему образцу. Образцы снимаются один раз. Владелец проходит сценарии руками на
тестовом аккаунте, а `exch record` в это время только слушает и пишет всё в файл. Сам он ничего
не отправляет и ничего не нажимает. Из файла получаются фикстуры для парсеров и сценарии для
симулятора. Тесты прогоняют их при каждом изменении кода.

## Что уже проверено, а что нет

| Что | Откуда сейчас | Статус |
|---|---|---|
| Ссылки и коды чеков (`CQ…`, `t_…`, `mci_…`, `mc_…`), закреплённые id ботов | ловец lovec, боевые логи | **проверено** |
| Открытие чека: `/start <код>`, порядок разбора ответов, ловушки (повтор, «не найден» у свежего чека xRocket, FLOOD_WAIT) | ловец lovec: код и аудиты, словари с боевой частотой | **проверено логикой ловца**; полных текстов ответов нет — их даст запись |
| Создание чека: инлайн `@send 10usdt` / `@xrocket 10`, запасной путь через меню | описание владельца, допущения LOVEC-PORTING §8.1–8.2 | **не проверено**, только симулятор |
| Оплата счёта: кнопка валюты → «Оплатить» в чате, без код-пароля | сообщение владельца 6 ноября (DESIGN-v0.2 Р4) | **не проверено**: тексты карточки и ответов синтетические |
| Экран «Кошелёк», список своих чеков, «Ваш чек активировал…», входящий перевод | допущения | **не проверено** |

Пока строка «не проверено» не закрыта записью, этот сценарий на живых деньгах не включается.

Без записи сценарии тоже не поломают деньги. Любой незнакомый ответ кошелька даёт `Unknown`:
- направление встаёт на паузу;
- приходит алерт;
- заявка уходит человеку.

Вывести деньги можно только одной попыткой. Повторно нажимать «Оплатить» или создавать чек
вслепую бот не будет никогда (CLAUDE.md, правила 4–6 и 13).

## Подготовка

1. **Тестовый аккаунт Telegram.** Не основной и не будущий рабочий. Включите облачный пароль.
   Язык Telegram — русский: так боты ответят по-русски, как будут отвечать в работе.
2. **Деньги:** 5–10 USDT в CryptoBot и 5–10 USDT в xRocket на этом аккаунте.
3. **Второй аккаунт** — ваш основной или знакомого. С него создаются чеки и счета для тестового.
4. **CryptoBot → «Безопасность» → «Лимит без код-пароля».** Запишите, сколько стоит. Для теста
   хватит $500 по умолчанию.
5. **Сервер:** `.env` с `DATABASE_URL`, `TG_API_ID`, `TG_API_HASH`, `SESSION_KEY`, затем
   ```bash
   exch migrate
   exch login --label test-1 --platform cryptobot   # номер, код из Telegram, облачный пароль — в терминале
   exch login --label test-1 --platform xrocket     # та же сессия, без кода
   ```

## Запись

```bash
exch record --label test-1 --out ~/rec-test-1.jsonl --history 300
```

`--history 300` сразу сохранит последние 300 сообщений каждого чата: с @send, с @xrocket и
«Избранное». Если тестовым аккаунтом уже пользовались ботами, это готовые образцы. Дальше запись
идёт, пока не нажмёте Ctrl-C.

Пока запись идёт, сделайте руками в Telegram на тестовом аккаунте шаги ниже. Делайте по порядку,
с паузой 5–10 секунд между шагами, чтобы бот успел ответить. Номер шага записывайте на бумажке
или в заметках: так я сопоставлю шаг с ответом.

### А. Кошелёк

1. @send → «Кошелёк».
2. @xrocket → «Кошелёк».

### Б. Создание чека (главное для выплат)

3. В «Избранном» наберите `@send 1usdt`. Над клавиатурой появятся варианты. Выберите чек на
   1 USDT и отправьте.
4. Подождите 10 секунд. Сообщение может само поменяться, когда чек будет готов.
5. В «Избранном» наберите `@xrocket 1` и тоже отправьте чек на 1 USDT.
6. @send: `/checks` → «Создать чек» → USDT → `1`. Пройдите до конца и запомните все экраны.
7. @xrocket: `/cheques` → «Персональный» → «Создать чек» → USDT → `1`.
8. @send: откройте список своих чеков. Удалите один неактивированный, если бот это позволяет.
9. @xrocket: то же.
10. Создайте чек больше баланса, например `@send 1000usdt`, — посмотреть отказ.

### В. Открытие чеков (приём денег)

Создайте чеки на втором аккаунте и откройте ссылки тестовым:

11. обычный чек CryptoBot на 1 USDT;
12. тот же чек ещё раз — «уже активирован»;
13. обычный чек xRocket на 1 USDT;
14. мульти-чек CryptoBot на 2 активации по 0.5 USDT;
15. мульти-чек xRocket — бот должен отказать, нужен его ответ;
16. чек CryptoBot, созданный для другого пользователя, если бот это умеет, — «не для вас»;
17. ссылку на несуществующий чек (испортите в ней последнюю букву) — «не найден».

### Г. Оплата счетов

18. Второй аккаунт: @send → «Счета» → создать одноразовый счёт на 1 USDT. Тестовый: открыть
    ссылку → USDT → «Оплатить». Запишите, спросил ли бот код-пароль и открылось ли мини-приложение.
19. Открыть ту же ссылку ещё раз — «уже оплачен».
20. Второй аккаунт: счёт на сумму больше баланса тестового. Тестовый: открыть → «Оплатить» —
    «недостаточно средств».
21. То же для xRocket: счёт на 1 USDT → тестовый открыть → USDT → «Оплатить».

### Д. Уведомления

22. Второй аккаунт открывает чек, который тестовый создал в шагах 3–7. Тестовому придёт
    «Ваш чек активировал…».
23. Второй аккаунт переводит тестовому 0.1 USDT напрямую, если бот это умеет. Тестовому
    придёт «Вы получили…».

Остановите запись Ctrl-C.

## Передача файла

- **Ссылки:** в файле живые ссылки на чеки. К моменту передачи все тестовые чеки должны быть
  открыты или удалены (шаги 22, 8–9). Тогда ссылки ничего не стоят.
- **Чего в файле нет:** сессии, ключей и номера телефона в нём нет: `exch record` пишет только
  сообщения чатов с ботами и «Избранного».
- **Как передать:** пришлите файл сюда, в чат, вместе со списком «номер шага → что получилось».
  В репозиторий файл не попадает. Коды я замаскирую и сделаю фикстуры.

## Что дальше

1. **Фикстуры.** Каждый ответ становится фикстурой в `crates/parsers/tests/fixtures/` с отметкой
   «живой». Синтетические строки, которые не совпали с живыми, исправляются или удаляются.
2. **Симулятор по живым текстам.** Тексты, кнопки и порядок правок берутся из записи. Все тесты
   движка и сценариев прогоняются на нём.
3. **Пробный прогон (`exch probe`, будет).** Запись не видит всплывающих ответов на нажатия кнопок:
   их видит только тот, кто нажал. Поэтому юзербот сам проходит каждый сценарий на тестовом
   аккаунте суммами по 1 USDT. Каждый шаг он подтверждает в терминале и останавливается на первом
   незнакомом экране.
4. **Только после этого** сценарий включается на рабочих аккаунтах: сначала с малыми лимитами
   (HANDOVER, M6).
