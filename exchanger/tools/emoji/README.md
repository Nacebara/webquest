# Эмодзи exch

Собственное семейство премиум-эмодзи бота в двух вариациях (решение владельца, 6 ноября 2026):

- **анимированная** — векторные TGS (Lottie), `assets/emoji/{color,mono}/*.tgs`;
- **статичная** — те же значки в позе покоя (`t = null`), PNG 100×100, как Telegram требует
  для статичных кастомных эмодзи: `assets/emoji/static/{color,mono}/*.png` (`static.js`).

`assets/emoji/manifest.json` — список значков для установки: вид, подпись, обычный эмодзи
(Telegram просит его для каждого кастомного), файлы обеих вариаций. Всё коммитится.

Установка в Telegram — `exch emoji install --owner <ваш Telegram id>` (нужен `CLIENT_BOT_TOKEN`,
владелец должен был написать боту `/start`): четыре набора кастомных эмодзи клиентского бота —
анимированные и статичные, плитки и линии. Линии Telegram перекрашивает в цвет текста, а это
свойство всего набора, поэтому их наборы отдельные. Повторный запуск дописывает недостающее
и обновляет id в `settings.emoji_packs`.

| Команда | Что делает |
|---|---|
| `exch emoji show` | вариация, сколько значков в наборах, источник эмодзи каждой роли |
| `exch emoji style animated` / `static` / `off` | вариация набора; `off` — обычные символы |
| `exch emoji set <роль> <id>` | свой премиум-эмодзи на роль, сильнее набора (как в боте-гаранте) |
| `exch emoji reset <роль>` | роль снова из набора |

Клиентский бот читает настройки при старте (`exch run`). В пульте (ops-бот, M5) будут те же
действия кнопками: вариация, «Прислать свой эмодзи» на роль — бот возьмёт `custom_emoji_id`
из присланного сообщения.

| Набор | Что это | В Telegram |
|---|---|---|
| `color` (43) | Плитки и статусы: обмен, готово, ошибка, в работе, ждём, возврат, тревога, шаги, кольца прогресса, «выгодно» | без перекраски |
| `mono` (73) | Линейные значки для кнопок и строк: клиентские и админские (в том числе «выгодно», «встречный поток», «ступени») | `needs_repainting`: цвет текста темы |

Анимированы все (версия 2). Правило движения одно: короткий жест в начале петли (0,1–0,5 с),
дальше покой до конца петли 2,8 с. Постоянно движутся только живые состояния: `process` (три
точки волной), `wait`, `sending`, `manual`, `alarm`, `live`, `dot_wait`.

## Правила рисования

- Значок — функция `(t) => SVG` на сетке 24×24 в `icons.js`, `t` от 0 до 1, `t = null` —
  статичный вид. Кадры `t = 0` и `t = 1` должны совпадать: петля без скачка. Жесты — помощники `A`
  (`pop`, `turn`, `spin`, `swing`, `nudge`, `shake`, `blink`).
- Линии: на плитке 1,8 (после масштаба 1,5), моно — `MONO_W` = 1,6. Сплющивать линию
  неравномерным масштабом нельзя — двигайте геометрию (см. `eye`, `chart`, `pause`).
- Цвет только сплошной. Полупрозрачный цвет на тёмной теме выглядит грязным пятном.
  Исчезающее сжимается или истончается, а не тает.
- Анимация — один слой с преобразованием группы. Маски (трек-матт) и прозрачность групп
  rlottie смешивает по-своему, и сверка их ловит.
- Нельзя: `text`, `image`, `mask`, `filter`, `stroke-dashoffset`, `ellipse`, `line`, `polygon`
  (конвертер их не знает). Пунктир — `stroke-dasharray`, бегущая дуга — пунктир длиннее пути.
- У каждого значка есть подпись в `LABELS`: её показывают превью и админка.

## Сборка и проверка

```bash
cd tools/emoji && npm ci && cd ../..
python3 -m venv /tmp/emoji-venv && /tmp/emoji-venv/bin/pip install rlottie-python pillow numpy

node tools/emoji/check.js                         # петли бесшовны, подписи есть, нет запрещённого
node tools/emoji/tgs.js assets/emoji              # все значки; или: … assets/emoji swap,done
node tools/emoji/static.js assets/emoji           # статичная вариация и manifest.json
node tools/emoji/frames.js /tmp/emoji-ref 256     # эталонные кадры (librsvg)
/tmp/emoji-venv/bin/python -I tools/emoji/verify_tgs.py assets/emoji /tmp/emoji-ref
/tmp/emoji-venv/bin/python -I tools/emoji/preview.py assets/emoji /tmp/emoji-preview.png
```

`verify_tgs.py` рисует каждый TGS движком rlottie, как Telegram, и сравнивает с эталоном
на тёмном и светлом фоне. Он проверяет и требования Telegram: 512×512, 60 кадров/с, не
дольше 3 с, файл до 64 КБ.

Сверка не считает разницу до 3 уровней из 255 (8-битный градиент rlottie — ровный сдвиг цвета,
глазом не виден), а порог средней разницы — 0,8: сдвиг контура на 1 px из 256 уже не проходит.
Пороги не ослаблять. Если значок не проходит, меняйте рисунок.
`preview.py` — лист для глаз: обе темы, 64 px и 20 px (размер в тексте), кадры петли.
Для `EXCH_JSON=1` рядом с каждым `.tgs` пишется `.json` (Lottie для веб-превью, lottie-web).

Конвертер и сверка перенесены из инструментов «Реборна». Отличия:
- толщина обводки анимируется;
- `verify_tgs.py` проверяет обе темы и не считает 8-битный сдвиг цвета (порог при этом строже);
- все значки анимированы, моно тоже.

Добавлены `check.js` и `preview.py`.
